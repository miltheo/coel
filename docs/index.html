Source Policy

Classification model CSV registries are the canonical model artefacts and IRI targets. JSON and Turtle serialisations are derived outputs generated from the CSV registries by the reusable R conversion utilities.

Folder paths use behavioural_bout; file names use behavioural-bout. Stable IRIs in registry iri columns should not be changed without release governance review.

Quick Start

Validate Atom payloads

Use the Atom v2.0 JSON Schema with the validation utilities for example and implementation payloads.

Rscript utilities/code/COEL_payload_validation.R

Export JSON-LD

Apply the published context to structurally valid Atom JSON payloads for linked-data workflows.

Rscript utilities/code/COEL_Atoms_to_jsonld.R

Aggregate through mappings

Use mapping CSV files to connect implementation-specific labels to COEL Model v2.0 concepts.

Rscript utilities/code/COEL_jsonld_cq7_cq8.R

Regenerate derived files

Regenerate JSON and Turtle serialisations from the canonical model and mapping CSV files.

Rscript utilities/code/COEL_model_csv_to_ttl.R

Citation, Licence, and Governance

Cite the versioned repository release used in your work, and cite OASIS COEL v1.0 where that standard is relevant. Licence information is provided in LICENSE.

Updates should preserve stable IRIs, keep CSV registries as the source of truth for classification models, and document regenerated derived artefacts in release notes.
